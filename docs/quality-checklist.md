# 要件・品質チェックリスト

レビュー時は各項目を `未確認`、`合格`、`要修正`、`対象外（理由を記録）` のいずれかで記録する。未確認を合格として扱わない。教材・出典に関する確認待ちは、実装機能が動作しても教材公開・通常出題の合格を意味しない。

## A. 要件・対象範囲

- [ ] 対象が2級建築施工管理技士「仕上げ」に限定され、他種別・種別不明の教材を取り込まない。
- [ ] 対象年度・試験回、対応端末、保存先、バックアップ先が決まっている。
- [ ] 4択式、記述式、履歴、バックアップ、設定インポートの利用シナリオと受入条件が定義されている。
- [ ] 未決事項に担当・確認方法・保留中の影響が記録されている。

## B. 教材の信頼性・出典

- [ ] 各コンテンツが「公式過去問」「公式正答」「CIC参考答案」「AI解説」「AI練習問題」のいずれかに分類され、区分が画面上でも分かる。
- [ ] 公式過去問と公式正答の出典・確認を別々に持つ。公式問題であることだけを理由に正答を公式扱いしていない。
- [ ] CIC参考答案を公式正答と混同せず、参照した資料・版・ページを記録している。
- [ ] AI解説は生成元、対象の問題・正答、生成／人手確認状態を追跡でき、公式見解と誤認させない。
- [ ] AI練習問題は過去問と別の出題群・表示区分にあり、過去問の転載や軽微な言い換えを新規問題としていない。
- [ ] `確認待ち`・`差戻し` の教材は通常出題・採点に入らず、管理画面に状態が表示される。
- [ ] 問題、選択肢、正答、答案、解説のそれぞれについて、出典名とページを確認できる。
- [ ] PDFページ番号と印刷ページ番号を混同せず、必要に応じて両方を記録している。
- [ ] 仕上げ種別が確認できない資料を推測で分類していない。対象外・保留の判断を記録している。
- [ ] 資料の利用条件を確認し、保留中または許諾範囲外のデータを配布対象に含めていない。

## C. PDF抽出品質

- [ ] 一括抽出前に、レイアウトの異なる代表5〜10ページを選んで原本照合した。
- [ ] 設問番号、否定表現、数値、単位、選択肢、図表参照、改ページ後の続きに誤り・欠落・重複がない。
- [ ] 正答に影響する不一致があった場合は、修正後に再検証するまで一括取込を停止した。
- [ ] 図表・写真が必要な問題は、設問と対応する図表を確認できる。
- [ ] 検証ページ、抽出条件、結果、修正内容を記録し、全件データの出典ページを保持した。

## D. 4択式の受入基準

- [ ] 各問題に選択肢が4つあり、選択肢ID・表示順が一意である。欠落・重複のある問題は出題されない。
- [ ] 確認済み正答が1つだけ設定され、回答前に正答が漏れない。
- [ ] 回答を確定すると正誤と、根拠の区分・解説・出典ページが表示される。
- [ ] 公式正答が未確認の問題は、正誤を断定する採点対象にしない。
- [ ] 出題順の変更があっても選択肢と正答の対応が壊れない。
- [ ] 二重クリック、画面再読込、保存失敗で同一回答履歴が意図せず重複しない。

## E. 記述式の受入基準

- [ ] 回答を入力・確定し、画面再表示後も履歴から入力内容または定めた保存要約を確認できる。
- [ ] 模範答案・採点観点には教材区分、確認状態、出典ページが表示される。
- [ ] CIC答案・AI解説・AI生成答案を公式正答として表示しない。
- [ ] 根拠の確認できる採点基準がない場合は自動で正誤・得点を断定せず、参考答案との自己確認として扱う。
- [ ] 空欄、長文、改行、特殊文字を扱っても画面や保存データが壊れない。

## F. 学習履歴の受入基準

- [ ] 履歴に日時、問題ID、教材データ版、回答形式、回答内容、採点状態・結果を関連付けて保存する。
- [ ] アプリを再起動しても履歴が残り、日時順に閲覧できる。
- [ ] 履歴の集計値と個別回答の内容が一致する。公式問題・AI練習問題などの区分を混ぜて集計しない。
- [ ] 問題データが更新・削除された場合も、過去履歴の由来を確認できるか、参照不能として明確に表示する。
- [ ] 保存失敗時に成功したように見せず、再試行可能な説明を表示する。

## G. バックアップ／復元の受入基準

- [ ] バックアップ形式にバージョンがあり、対象に含むデータ（履歴・設定等）と含めない教材データを明記する。
- [ ] 書き出したバックアップを別の空状態へ復元し、履歴・設定の件数と内容が一致する。
- [ ] 復元前にファイル形式・バージョン・必須項目・値を検証し、プレビューまたは復元対象の説明を表示する。
- [ ] 不正・途中欠損・非対応バージョンのファイルでは復元全体を中止し、既存の履歴・設定を変更しない。
- [ ] 復元処理中の失敗は一部データだけを反映せず、開始前の状態へ戻せる。
- [ ] 教材データ版が異なる場合、履歴を誤った問題へ結び付けず、不一致・孤立した履歴を明示する。
- [ ] バックアップに教材本文・PDF・OCR等を含める場合は、権利・保存先・暗号化等の要件を別途承認している。未承認なら含めない。

## H. 設定インポートの受入基準

- [ ] 設定ファイルは学習履歴・教材データのバックアップと区別される。
- [ ] 対応形式・バージョンと取り込む設定項目を事前に確認できる。
- [ ] 型・値域・列挙値を検証し、不正値や非対応バージョンでは既存設定を変更しない。
- [ ] インポートの確定後にのみ設定を反映し、完了・失敗を表示する。
- [ ] 欠落項目・未知項目の扱い（既定値、無視、警告等）が仕様化され、利用者に分かる。
- [ ] 設定反映後、アプリ再起動後も有効であり、履歴や教材データに意図しない変更がない。

## I. 公開・運用・リリース

- [ ] 公開GitHubにはアプリコード、仕様、合成テストデータのみを置き、実教材データを置かない。
- [ ] 公開前に未追跡・追跡済み・ステージ済みファイル、差分、配布物を確認した。
- [ ] PDF原本、画像、OCR結果、問題文、選択肢、正答、CIC答案、教材に由来するAI解説・練習問題が公開対象に含まれない。
- [ ] `.gitignore`だけに依存せず、実データの保管場所を公開リポジトリ外に分けている。
- [ ] バックアップの保管・復元手順と、障害時の問い合わせ・復旧方針が用意されている。
- [ ] 実装計画のPhase完了条件と [テスト項目](../tests/README.md) の結果が記録されている。

## 判定

- **リリース可**: 対象範囲、データ出典、対象種別、必須機能、バックアップ・インポート、公開前確認がすべて合格。
- **条件付き**: 明確に分離された任意機能のみ未完了で、教材誤認・データ損失・公開混入のリスクがない。制限と対応時期を記録。
- **リリース不可**: 出典・正答・仕上げ種別が確認待ちの教材を通常出題する、無効ファイルで既存データを破損する、または公開物に教材データが含まれる。
