# 実装計画（Phase 1〜3）

## 1. 目的と前提

2級建築施工管理技士の学習を支援するアプリを、まず「仕上げ」種別に限定して段階的に実装する。過去問、正答、参考答案、AI生成物の出所と確からしさを区別し、学習履歴を安全に保持・復元できることを重視する。

この文書は要件・品質レビュー用の計画であり、実装技術や保存先が未確定の項目は Phase 1 で決定する。要件が確定するまでは、未確認の教材を正答や公式情報として扱わない。

### 対象範囲

- 対象資格・種別: 2級建築施工管理技士「仕上げ」。他の種別・級は対象外。
- 問題形式: 4択式、記述式。
- 学習機能: 解答、結果・解説表示、学習履歴。
- 運用機能: データのバックアップ／復元、設定のインポート。
- 教材データ: 公式過去問、公式正答、CIC参考答案、AI解説、AI練習問題を別区分で管理。

### 先に決める事項

- 対応端末・実行環境、ローカル／サーバー保存の別、バックアップの保存先。
- 対象年度・試験回、参照する公式サイトやCIC資料の具体的な版。
- CIC資料・公式資料の利用条件と、アプリ内保存・配布が認められる範囲。
- 記述式を自己採点にするか、採点基準・模範答案をどう表示するか。

これらが決まるまでは、保存方式・採点方法・教材の公開可否を前提に実装を固定しない。

## 2. 教材データの共通ルール

### 区分と表示

| 区分 | 扱い |
| --- | --- |
| 公式過去問 | 公式資料に掲載された問題本文。年度・試験回・問題番号・出典ページを紐づける。 |
| 公式正答 | 試験実施機関等が公式に公表した正答。公式過去問とは独立して出典と確認状態を記録する。公式の正答が見つからない場合は推定で補わない。 |
| CIC参考答案 | CICの資料に基づく参考答案。公式正答と同一視せず、「CIC参考答案」と明示する。 |
| AI解説 | AIが作成した説明。根拠となる問題・正答・参照ページと生成／人手確認状態を記録し、公式見解のように表示しない。 |
| AI練習問題 | AIが新規作成した演習問題。過去問と混ぜず、「AI練習問題」と表示する。過去問の転載・軽微な言い換えを新規問題として扱わない。 |

1問ごとに少なくとも、教材区分、対象種別、年度・試験回（該当する場合）、問題番号、出典名、出典URLまたは資料識別子、出典ページ、確認状態、確認者・確認日を持たせる。正答・答案・解説は問題本文とは別の出典と確認状態を持たせる。

確認状態は `確認待ち`、`確認済み`、`差戻し` を基本とする。`確認待ち` と `差戻し` の教材は通常の出題・採点対象から除外し、管理・確認画面では状態を明示する。確認済みにするには、問題本文、選択肢や設問条件、正答・答案、出典ページ、仕上げ種別の各項目を人が照合する。

### PDF抽出とページ記録

1. PDF全体を一括登録する前に、レイアウトや内容が異なるページを含む5〜10ページを選び、抽出結果を原本と目視照合する。
2. 問題番号、設問文、否定表現、数値、単位、選択肢、図表参照、改ページによる続きが一致することを確認する。正答に影響する不一致が1件でもあれば一括取込を止め、抽出方法を修正して再検証する。
3. 問題ごとにPDF上のページ番号と、資料に印刷されたページ番号を区別して記録する。両者が同じと推定して記録しない。
4. 検証済みサンプルの範囲・結果・抽出条件を記録し、その後の全件取込でも問題単位で出典ページを保持する。図や表に依存する問題は、画像・図表を確認できない状態で確認済みにしない。

### 仕上げ種別の限定

- 取込・登録時に対象種別が「仕上げ」と明確に確認できる教材だけを採用する。
- 他種別、種別不明、混在教材のうち仕上げ問題と特定できないものは、通常問題バンクへ登録せず `確認待ち` または対象外とする。
- 種別名の欠落を推測で補完したり、他種別の問題を仕上げ用に自動変換したりしない。
- 画面、検索、出題、集計、インポート検証のすべてで同じ種別制約を適用する。

## 3. Phase別計画

### Phase 1: 要件・データ基盤の確定

**実施内容**

- 対象端末、保存方式、データ形式、対象年度・試験回、使用資料と利用条件を決める。
- 問題・正答・答案・解説・出題履歴のデータ項目と、出典・区分・確認状態の表現を定義する。
- 仕上げ種別の判定基準、確認待ちデータの隔離方法、公開リポジトリへ教材を置かない運用を確定する。
- PDFの代表5〜10ページで抽出方式を試し、照合記録と取込可否を作成する。
- 受入基準とテスト項目をレビューし、未決事項を解消または明示する。

**成果物**: 確定要件、データ仕様、出典・確認手順、PDF抽出検証記録、リスク一覧。

**完了条件**: 学習端末・保存先・教材の利用条件が決まり、代表ページの重要情報に不一致がなく、仕上げ種別と出典を追跡できる。未解決の権利・正答・種別確認がある資料は取込対象から除外する。

### Phase 2: 学習機能の最小版

**実施内容**

- 確認済みの仕上げ教材だけを読み込み、教材区分と出典を学習画面に表示する。
- 4択式の回答、採点、回答後の解説・出典表示を実装する。
- 記述式の回答入力と、確認済み答案・採点観点の表示を実装する。採点の根拠が確立するまでは自動判定せず、自己採点用の参考情報として扱う。
- 解答日時、問題ID、回答内容、結果、教材データ版を履歴として保存し、再起動後も閲覧できるようにする。
- 設定の閲覧・変更と、設定インポートの最小仕様を実装する。

**完了条件**: 4択・記述式・履歴・設定インポートの受入基準を満たし、確認待ち教材が通常出題に混入しない。未確認の正答やAI生成物が公式教材に見える表示にならない。

### Phase 3: 保全・復元・リリース品質

**実施内容**

- 学習履歴と設定のバックアップ書き出し、検証付き復元、形式バージョン管理を実装する。
- 不正・途中で壊れたファイルの取込、データ版不一致、復元中断時の挙動を確認する。
- 教材を含まない合成データで、データ移行・境界条件・回帰テストを行う。
- 公開前にGit追跡対象・ステージ済み変更・配布物を点検し、教材本文、PDF、画像、OCR、正答、答案、実データを除外する。
- 操作手順、バックアップ保管・復元手順、既知の制限を整備する。

**完了条件**: バックアップから履歴と設定を復元でき、無効な入力で既存データが壊れず、公開対象に教材データが含まれないことを確認する。権利・出典・対象種別に未確認事項がある教材はリリース用データに含めない。

## 4. 主なリスクと対策

| リスク | 対策 |
| --- | --- |
| OCR誤りが正答・学習を誤らせる | 代表5〜10ページの事前照合、正答に影響する差異があれば取込停止、出典ページ単位の確認。 |
| 参考答案やAI出力が公式情報と誤認される | データ区分と確認状態を回答画面まで表示し、公式正答と別管理する。 |
| 他種別の問題が混ざる | 登録時と出題時の両方で仕上げ種別を検証し、不明データは隔離する。 |
| 教材の権利・利用範囲が不明 | 利用条件確認前は公開・配布しない。疑義のある教材は取込を保留する。 |
| 履歴や設定の破損・消失 | 版付きバックアップ、復元前検証、失敗時の全件ロールバック、復元手順を用意する。 |
| GitHub公開時に教材が混入 | 実教材を公開リポジトリ外で管理し、公開前に追跡・差分・成果物を確認する。`.gitignore`だけを安全策とみなさない。 |

## 5. 将来拡張

他の級・種別の追加、許諾確認済み教材の追加、出題範囲・年度別分析、苦手問題の再出題、複数端末同期、記述答案のルーブリック採点を候補とする。いずれも現行の仕上げ種別制約と教材区分を崩さず、権利・正答根拠・品質確認の基準を定義してから着手する。AIによる採点を追加する場合も、AI評価を公式採点と表示せず、採点根拠・人手確認方法・誤判定時の扱いを別途受入条件にする。
