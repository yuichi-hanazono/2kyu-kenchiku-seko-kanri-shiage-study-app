# テスト計画

この文書は、実装時に実施するテスト項目と合格条件を定める。現時点では技術スタック・テストランナーが未確定のため、コマンド名は実装環境決定後に追記する。教材の検証には実際の試験問題を含む公開テストデータを使わず、合成データを用いる。

## テスト方針

- 問題データの検証、採点、履歴、設定、バックアップ形式の単体テストを行う。
- 画面操作と保存・復元をつなぐ結合テストを行う。
- PDF抽出は代表5〜10ページの目視照合を含む手動確認を行い、ページと結果を記録する。
- 教材出典・正答・仕上げ種別の承認と、公開GitHubへの教材混入確認は、リリース担当者がチェックリストで確認する。
- 自動テスト合格だけで教材の内容・正答・権利確認済みとは判定しない。

## テストデータの安全ルール

- 自動テスト、スクリーンショット、サンプル設定、デモ画面には架空の設問と架空の選択肢を使う。
- 公式過去問、正答、CIC参考答案、PDF画像、抽出OCR、これらを元にしたAI解説・AI練習問題を公開リポジトリのfixture・snapshot・ログに含めない。
- 実教材を用いた手動確認が必要な場合は、アクセス制御されたローカルまたは承認済みの保管場所を使用し、テスト後の出力物やログへの残存を確認する。
- 氏名、アカウント情報など学習に不要な個人情報を履歴・テストデータへ含めない。

## テスト項目

| ID | 対象 | 確認内容 | 合格条件 |
| --- | --- | --- | --- |
| DATA-01 | データ分類 | 5区分を登録・表示する | 公式過去問、公式正答、CIC参考答案、AI解説、AI練習問題の区分が保存・表示で維持される。 |
| DATA-02 | 確認状態 | 確認待ち・差戻しデータを検索・出題する | 通常出題・採点に現れず、管理画面で状態と保留理由を確認できる。 |
| DATA-03 | 出典 | 出典ページのない教材を検証する | 確認済みにできず、出題対象として有効化されない。 |
| DATA-04 | 種別制限 | 仕上げ、他種別、種別不明のデータを取り込む | 仕上げのみ採用され、他種別は拒否、種別不明は確認待ちへ隔離される。 |
| DATA-05 | PDF抽出 | 代表5〜10ページを原本と照合する | 問題番号、設問、否定表現、数値・単位、選択肢、図表参照、ページ対応に重要な不一致がない。問題に影響する不一致時は取込が停止する。 |
| QUIZ-01 | 4択表示 | 選択肢4つ、欠落・重複・順序変更を検証する | 4選択肢が正しく表示され、無効データは出題されない。順序変更後も正答IDが正しい。 |
| QUIZ-02 | 4択採点 | 各選択肢を回答する | 確認済み正答だけを基準に一度だけ採点され、回答後に区分・解説・出典が表示される。 |
| QUIZ-03 | 正答未確認 | 正答が確認待ちの問題を回答する | 正誤・得点を断定する採点が行われない。 |
| WRITE-01 | 記述入力 | 空欄、改行、長文、特殊文字を入力し保存する | 定めた入力制限に従い、表示・保存・再表示で内容が壊れない。 |
| WRITE-02 | 記述参考答案 | 公式、CIC、AI由来の答案を表示する | 区分・確認状態・出典が分かり、未確認答案を公式正答として表示しない。根拠なしの自動採点がない。 |
| HIST-01 | 履歴保存 | 回答後に再起動し履歴を確認する | 日時、問題ID、回答、採点状態・結果、データ版が関連付いて保存される。 |
| HIST-02 | 履歴整合性 | 複数回回答、画面再読込、集計を行う | 意図しない重複がなく、明細と集計値が一致する。 |
| HIST-03 | 問題更新 | 問題IDまたはデータ版が変わった履歴を表示する | 旧履歴を別問題に誤結合せず、参照不能や版違いを明示する。 |
| BACK-01 | バックアップ | 履歴・設定を書き出す | 形式バージョンと対象範囲が分かり、規定外の教材本文を含まない。 |
| BACK-02 | 復元 | 空の環境へバックアップを戻す | 履歴・設定が元と一致し、件数と重要項目を確認できる。 |
| BACK-03 | 不正ファイル | 破損、必須値欠落、非対応版を復元する | 取込が中止され、既存データは処理前と同一である。 |
| BACK-04 | 復元中断 | 書込中の失敗を模擬する | 部分反映が残らず、開始前へ戻るか安全に再試行できる。 |
| BACK-05 | データ版不一致 | 教材版と履歴版が異なるバックアップを復元する | 履歴を別の問題に誤結合せず、不一致・孤立を表示する。 |
| SET-01 | 設定インポート | 正常な設定ファイルを取り込む | プレビューと確定後に設定が反映され、再起動後も維持される。履歴・教材は変化しない。 |
| SET-02 | 無効な設定 | 型違い、範囲外値、未知項目、非対応版を試す | 定義済み方針どおりに警告・無視または中止し、無効ファイルで既存設定が壊れない。 |
| PUB-01 | 公開物点検 | Git追跡・差分・配布物・テスト出力を確認する | 実教材の本文、正答、PDF、画像、OCR、派生AIコンテンツが含まれない。 |

## 手動受入確認

1. 仕上げ種別の確認済み合成問題を登録し、4択・記述式をそれぞれ回答する。
2. 区分、正答／参考答案の状態、出典ページが回答結果に表示されることを確認する。
3. 確認待ち、他種別、種別不明、出典ページ欠落の合成データが通常出題から除外されることを確認する。
4. 履歴を確認し、アプリ再起動後も回答・採点状態・データ版が維持されることを確認する。
5. バックアップを書き出し、新しい環境への復元と不正ファイルでの復元失敗を確認する。失敗後に既存データが変わっていないことを比較する。
6. 設定だけをインポートし、履歴・教材に変更がないことを確認する。
7. 公開前チェックで、公開対象に教材由来のデータ・ログ・画像がないことを確認する。

## Phaseごとのゲート

- **Phase 1**: DATA-01〜05の仕様が確定し、PDFの代表ページ照合記録がある。利用条件、保存先、出典項目の未決事項を記録する。
- **Phase 2**: QUIZ-01〜03、WRITE-01〜02、HIST-01〜03、SET-01〜02が合格する。教材確認状態が出題制御に反映される。
- **Phase 3**: BACK-01〜05、PUB-01、手動受入確認が合格する。無効データの復元による破損がなく、公開対象から教材が除外される。

テスト結果には、実行日、アプリ／データ版、確認者、合否、再現手順、未解決事項を残す。未実施は「合格」ではなく「未確認」と記録する。

## 将来追加するテスト

- 他の級・種別を追加する場合の境界テスト（仕上げ問題との混在・誤分類防止）。
- 苦手問題の再出題、年度別分析、複数端末同期のデータ整合性テスト。
- 許諾済み教材の追加時のライセンス表示・配布範囲確認。
- 記述式のルーブリック採点やAI支援を導入する場合の採点根拠、誤判定、人手確認、説明可能性の評価。
